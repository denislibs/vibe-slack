# Client MLS 6.3a — crypto-core external commit + GroupInfo + worker plumbing

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Expose MLS `GroupInfo` export and external-commit join in the Rust crypto engine (so a client can join a public channel without an existing member adding it), plumb them through the crypto worker (protocol/worker/CryptoClient), and prove an end-to-end external-commit round trip through the real WASM.

**Architecture:** `crypto-core` (OpenMLS 0.6, Rust→WASM via wasm-pack `--target web`) gains `export_group_info` + `join_by_external_commit` on `Engine` and `WasmEngine`. The TS crypto layer (`client/src/shared/lib/crypto/{protocol.ts,worker.ts,client.ts}`) gains matching request kinds. Existing members apply the external commit via the already-generic `process`/`decrypt` path.

**Tech Stack:** Rust (openmls 0.6, `use_ratchet_tree_extension(true)` already on), wasm-pack, TypeScript, vitest.

**Conventions (verified):**
- `Engine` (`crypto-core/src/engine.rs`): groups in `HashMap<Vec<u8>, MlsGroup>`; `create_group` builds with `MlsGroupCreateConfig::builder().ciphersuite(DEFAULT_CIPHERSUITE).use_ratchet_tree_extension(true)`. `add_member` returns `AddResult{commit, welcome}` (group_info discarded). `join_from_welcome` uses `MlsMessageIn::tls_deserialize_exact` + `.extract()` match. `process` handles `StagedCommitMessage` (merges) — external commits arrive here as normal commits. Errors via `EngineError::mls`/`::serde`. `tls_codec::{Serialize, Deserialize}` in scope.
- `WasmEngine` (`crypto-core/src/lib.rs`): thin wrappers returning `Result<_, JsError>` via `to_js`; `WasmAddResult` getter pattern for multi-field returns.
- wasm-pack rebuild: after changing Rust, rebuild the committed `client/src/shared/lib/crypto/wasm-pkg/` (the build command is in the crypto-core README or prior commits; `wasm-pack build --target web --out-dir <client wasm-pkg path>`). NOTE: wasm-pack regenerates a `.gitignore` with `*` inside the out-dir — `rm -f` it so the committed pkg stays tracked.
- TS crypto worker: `protocol.ts` is a discriminated union of request kinds + `CryptoResponse`; `worker.ts` has ONE shared `dispatchTo(engine, req)`; `client.ts` `CryptoClient` proxies via `send({kind,...})`. Mirror the existing `createGroup`/`addMember`/`joinFromWelcome` entries exactly.

```rust
/// Export the group's GroupInfo (with ratchet tree) so a new member can join
/// a PUBLIC channel via an external commit. Not a secret: the ratchet tree is public.
pub fn export_group_info(&self, group_id: &[u8]) -> Result<Vec<u8>, EngineError> {
    let group = self.groups.get(group_id)
        .ok_or_else(|| EngineError::UnknownGroup(hex(group_id)))?;
    let msg = group
        .export_group_info(self.provider.crypto(), &self.identity.signer, true) // with_ratchet_tree = true
        .map_err(EngineError::mls)?;
    msg.tls_serialize_detached().map_err(EngineError::serde)
}

/// Join an existing group by external commit, using only its published GroupInfo.
/// Returns the external commit message to fan out to existing members.
pub fn join_by_external_commit(&mut self, group_info_bytes: &[u8]) -> Result<Vec<u8>, EngineError> {
    let msg_in = MlsMessageIn::tls_deserialize_exact(group_info_bytes).map_err(EngineError::serde)?;
    let verifiable_group_info = match msg_in.extract() {
        MlsMessageBodyIn::GroupInfo(gi) => gi,
        _ => return Err(EngineError::Mls("expected a GroupInfo message".into())),
    };
    let config = MlsGroupJoinConfig::builder().use_ratchet_tree_extension(true).build();
    let (mut group, commit, _group_info) = MlsGroup::join_by_external_commit(
        &self.provider,
        &self.identity.signer,
        None, // ratchet_tree: None — carried in GroupInfo
        verifiable_group_info,
        &config,
        // additional optional args per the pinned 0.6 signature (aad/capabilities/extensions),
        self.identity.credential_with_key.clone(),
    ).map_err(EngineError::mls)?;
    group.merge_pending_commit(&self.provider).map_err(EngineError::mls)?;
    let gid = group.group_id().as_slice().to_vec();
    self.groups.insert(gid, group);
    commit.tls_serialize_detached().map_err(EngineError::serde)
}
```
If `EngineError::mls` doesn't accept the `ExternalCommitError`/`ExportGroupInfoError` types, add `From`/map arms in `errors.rs` (follow the existing `EngineError::mls` generic-over-Display pattern).
